# 🎸 Melody Tab + Chord Shift

โปรเจกต์นี้มี 2 เครื่องมือ ทำงานในเบราว์เซอร์ทั้งหมด ฟรี ไม่ต้องใช้ API key:

- **Melody Tab** (`/index.html?page=melody`): แปลงไฟล์เพลงเป็นแท็บกีตาร์ (รายละเอียดด้านล่าง)
- **Chord Shift** (`/chords.html`): ใส่รูปคอร์ดเพลงแล้วเปลี่ยนคีย์ (ดูหัวข้อ [Chord Shift](#-chord-shift))

---

เว็บแอปแปลงไฟล์เพลงเป็นแท็บกีตาร์ (เมโลดี้) — ประมวลผลในเบราว์เซอร์ทั้งหมดด้วย AI model [basic-pitch](https://github.com/spotify/basic-pitch-ts) ของ Spotify ไม่มีการส่งไฟล์ขึ้นเซิร์ฟเวอร์

## วิธีใช้

```bash
npm install
npm run dev
```

เปิด http://localhost:5173/?page=melody แล้วลากไฟล์เพลง (MP3, WAV, M4A, OGG) มาวาง **หรือวางลิงก์ YouTube** แล้วกด "แกะโน้ตจาก YouTube" (จำกัดวิดีโอยาวไม่เกิน 15 นาที)

มีไฟล์ทดสอบให้ที่ http://localhost:5173/test-melody.wav (เมโลดี้ E4 G4 A4 B4 A4 G4 E4 D4)

> **หมายเหตุ YouTube:** ก่อนใช้ครั้งแรก รัน `npm run setup:youtube` เพื่อติดตั้ง `yt-dlp` จาก release ทางการพร้อมตรวจ SHA-256 ใน `.tools/` (ไม่เข้า Git) ใช้ Node.js 22 ขึ้นไปสำหรับแก้ JavaScript challenge ระบบใช้ `youtubei.js` อ่านชื่อ/ความยาว และใช้ `yt-dlp` ดาวน์โหลด M4A ให้เสร็จก่อนส่งไปแกะโน้ต ไม่ส่งไฟล์ที่โหลดค้างให้ AI (สูงสุด 32 MB และรอ 60 วินาที) หากมี yt-dlp อยู่แล้วใช้จาก PATH หรือกำหนด `YT_DLP_PATH` ได้ อัปเดตด้วยคำสั่ง setup เดิมเมื่อ YouTube เปลี่ยนระบบ
>
> ทดสอบ endpoint จริงด้วย `node scripts/test-youtube.mjs` หรือใส่ URL ต่อท้ายคำสั่งขณะเปิด `npm run dev` การอัปโหลดไฟล์จากเครื่องไม่ต้องติดตั้ง yt-dlp

## ปุ่มปรับแต่ง

- **เลือกช่วงโซโล่** — ใส่เวลาเริ่มต้น–สิ้นสุดเป็น `1:25` หรือ `85` วินาที (รองรับทศนิยม) เว้นสิ้นสุดว่างเพื่อแกะจนจบเพลง เลือกได้ก่อนอัปโหลด/ดึง YouTube หรือหลังโหลดแล้วกด **แกะช่วงที่เลือก** เพื่อแกะใหม่จากเสียงที่เก็บไว้ ไม่ดาวน์โหลดซ้ำ AI ประมวลผลเฉพาะช่วงนั้น และเวลาในแท็บ/ไฟล์ .txt ยังอ้างอิงเพลงต้นฉบับ
- **ฟังช่วงที่เลือก** — เล่นเสียงต้นฉบับจากจุดเริ่มและหยุดที่จุดจบ ใช้ปุ่ม **ใช้เวลาที่กำลังฟัง** ตั้งขอบเขตจากตำแหน่งเครื่องเล่น หรือ **เลือกทั้งเพลง** เพื่อคืนค่าเริ่มต้น
- **กีตาร์ไฟฟ้า / โซโล่** (ค่าเริ่มต้น) — เลือกแนวโน้ตที่ต่อเนื่องจากความดังและระยะห่างของโน้ต แทนการเลือกโน้ตดังสุดทุกครั้ง เป็นการคัดโน้ต ไม่ใช่การแยกเสียงเครื่องดนตรี
- **ช่วงเสียงกีตาร์ไฟฟ้า** — ลีดตั้งแต่ E3, รวมริฟฟ์เสียงต่ำตั้งแต่ E2 หรือโซโล่สูงตั้งแต่ E4 กรองเสียงนอกช่วงก่อนเลือกเมโลดี้
- **เฟรตสูงสุด** — เลือก 15, 21, 22 หรือ 24 (ค่าเริ่มต้น) โหมดกีตาร์ไฟฟ้าคงระดับเสียงเดิมและตัดโน้ตที่เกินช่วงออก ไม่เลื่อน octave ลง
- **ฟังเสียงต้นฉบับเทียบกับแท็บ** — มีเครื่องเล่นไฟล์ที่อัปโหลด พร้อมเวลาในแท็บอ้างอิงต้นฉบับ
- **ความไวการจับโน้ต** — เพิ่มถ้าโน้ตหาย ลดถ้าโน้ตเกินมาเยอะ
- **ตัดโน้ตสั้นกว่า** — กรองโน้ตผี/เสียงรบกวนสั้นๆ ออก
- **เอาเฉพาะแนวเมโลดี้** — เลือกไลน์ต่อเนื่องในโหมดกีตาร์ไฟฟ้า หรือโน้ตเด่นสุดในโหมดทั่วไป ปิดเพื่อเรียงทุกโน้ตในช่วงเสียงที่เลือก (ยังไม่ใช่แท็บคอร์ดพร้อมกัน)
- **ฟังโน้ตที่ถอดได้** — เล่นเสียงสังเคราะห์ของโน้ตที่ถอดมา เอาไว้เช็คหูว่าตรงกับเพลงไหม

## ข้อจำกัด

- ใช้เสียงกีตาร์เดี่ยวหรือไฟล์แยกเสียงกีตาร์จะได้ผลดีที่สุด — เพลงเต็มที่มีร้องและเครื่องดนตรีทับกันอาจจับเป็นเครื่องดนตรีอื่นได้ โหมดกีตาร์ไฟฟ้าไม่ได้แยก stem
- ยังไม่ถอดเทคนิค bend, slide, hammer-on, pull-off หรือ vibrato เป็นสัญลักษณ์แท็บ เสียงแตกและฮาร์โมนิกอาจทำให้ตรวจโน้ตเกิน
- จังหวะในแท็บเป็นแบบเรียงลำดับ ไม่ได้แบ่งห้องตามจังหวะจริง (ช่องว่างยาวแทนการเว้นวรรคเพลง)
- โหมดเมโลดี้ทั่วไปเลื่อนโน้ตนอกช่วงด้วย octave ให้เล่นได้ ส่วนโหมดกีตาร์ไฟฟ้ากรองออกและแสดงจำนวนโน้ตที่กรอง

## โครงสร้างโค้ด

- `server/youtube.js` — plugin `/api/youtube` ที่ใช้ใน `vite.config.js` ดึงและตรวจไฟล์เสียงจาก YouTube ฝั่งเซิร์ฟเวอร์ (เบราว์เซอร์โดน CORS บล็อก)
- `src/transcribe.js` — decode + resample เสียง แล้วรัน basic-pitch ได้ activation matrices ดิบ (cache ไว้ ปรับ setting ไม่ต้องรัน AI ใหม่)
- `src/melody.js` — กรอง polyphonic → เมโลดี้เดี่ยว โหมดทั่วไปเลือกโน้ตเด่นสุด โหมดไฟฟ้าใช้ dynamic programming เลือกไลน์ต่อเนื่องภายในช่วงเสียง
- `src/fretting.js` — เลือกตำแหน่งสาย/เฟรตด้วย Viterbi ให้มือขยับน้อยที่สุด (จูนมาตรฐาน เลือกได้ถึงเฟรต 24)
- `src/tab.js` — เรนเดอร์ ASCII tab
- `src/player.js` — เล่นโน้ตที่ถอดได้ด้วย Web Audio

# 🎼 Chord Shift

ใส่รูปคอร์ดเพลง (แคปหน้าจอหรือถ่ายรูปกระดาษ) แล้วเปลี่ยนคีย์ได้ทันที — ระบบหาตำแหน่งคอร์ดในรูปด้วย OCR ([Tesseract.js](https://github.com/naptha/tesseract.js)) แล้ววาดคอร์ดคีย์ใหม่ทับตำแหน่งเดิม เนื้อร้องภาษาไทยยังเป็นภาพต้นฉบับ จึงไม่มีปัญหาอ่านภาษาไทยผิด ทุกอย่างประมวลผลในเครื่อง ไม่อัปโหลดรูป

## วิธีใช้

```bash
npm install
npm run dev
```

เปิด http://localhost:5173 แล้ว

1. **ใส่รูป**: ลากมาวาง, แตะเลือกรูป, กด Ctrl+V วางรูปที่แคปไว้ หรือกด 📷 บนมือถือ (เพลงยาวเลือกหลายรูปพร้อมกันได้)
2. รอ 2–5 วินาที ระบบจะหาคอร์ด, เดาคีย์ต้นฉบับ และอ่านบรรทัดจูนสาย/คาโป้ (เช่น "Tune down ½ tone to Eb")
3. **แตะคีย์ที่ต้องการ** หรือกด − / + (คีย์บอร์ด `-` / `+`) คอร์ดในรูปจะเปลี่ยนเป็นสีน้ำเงิน

ตัวช่วย:

- **ไม่อยากจูนสายลง?** เพลงที่ต้นฉบับจูนต่ำ เปิดสวิตช์นี้แล้วระบบจะแปลงคอร์ดให้เล่นด้วยจูนมาตรฐานได้เสียงเท่าเดิม
- **🎯 เสียงเท่าเดิม แต่จับง่ายขึ้น** แนะนำตำแหน่งคาโป้ที่ทำให้จับคอร์ดเปิดได้ (เช่น คาโป้ 1 + คอร์ด C แทน Db)
- **✋ วิธีจับคอร์ด** ตารางนิ้วของทุกคอร์ดในคีย์ใหม่ แตะคอร์ดในรูปเพื่อดูตารางนิ้วหรือแก้ชื่อคอร์ดได้
- **🎸 โน้ตในคีย์บนคอกีตาร์** ตำแหน่งโน้ตของสเกลในคีย์ที่เลือก (ช่อง 0–15) เลือกได้ทั้งสเกลเต็มหรือเพนทาโทนิก ป้ายแสดงเป็นชื่อโน้ตหรือขั้น 1–7 ก็ได้ ถ้าใส่คาโป้จะนับตำแหน่งจากคาโป้ ให้ตรงกับคอร์ดที่จับ
- **➕ เพิ่มคอร์ดที่ขาด** ถ้ามีคอร์ดที่ยังไม่เปลี่ยน (ยังเป็นสีดำ) กดปุ่มนี้แล้วแตะคอร์ดนั้นในรูป
- **💾 บันทึกรูป / 📤 แชร์ / 🖨️ พิมพ์** ได้รูปคีย์ใหม่ไปใช้ต่อ
- **เพลงล่าสุด** เก็บรูปและคีย์ที่เลือกไว้ในเครื่อง (IndexedDB) เปิดซ้ำได้ทันที
- **ตัวเลือกเพิ่มเติม** ตั้งคาโป้ที่ใช้, เลือกเขียนแบบ ♯/♭, แก้คีย์ต้นฉบับหรือการจูนสายถ้าระบบอ่านผิด

## ข้อจำกัด

- รูปยิ่งคมยิ่งแม่น ทดสอบกับรูปตัวอย่างที่ย่อเหลือ 45% ถึงขยาย 200% และรูปที่มีเงา หาคอร์ดได้ครบ 34/34 ทุกแบบ ถ้าตัวคอร์ดสูงไม่ถึง ~8px อาจหลุดบ้าง ให้ใช้ ➕ เพิ่มเอง
- รองรับรูปพื้นดำ/ตัวหนังสือสี (dark mode) ระบบกลับขาว-ดำให้อัตโนมัติ และไฮไลต์คอร์ดที่เปลี่ยนเป็นสีเขียว
- รูปที่แบ่งเป็นหลายคอลัมน์ ระบบแยกแต่ละคอลัมน์มาเรียงลงมาให้อ่านง่ายบนมือถือ (ปุ่ม ▤ แยกคอลัมน์) ส่วนปุ่มบันทึกรูปยังได้รูปเต็มตามเลย์เอาต์เดิม
- ระบบวัดขนาดตัวอักษรในรูปก่อน แล้วขยายให้พอดีกับ OCR ทำให้ใช้ได้ทั้งแคปหน้าจอความละเอียดต่ำและสูง รูปใหญ่หลายคอลัมน์อาจใช้เวลา ~10 วินาที
- รูปถ่ายที่เอียงมากหรือกระดาษโค้งจะหาคอร์ดได้น้อยลง
- คอร์ดที่เขียนติดกับเนื้อร้องในบรรทัดเดียวกัน (ไม่ใช่บรรทัดคอร์ดแยกด้านบน) จะไม่ถูกหาเจอ

## โครงสร้างโค้ด (`src/chords/`)

- `theory.js`: แยกชื่อคอร์ด, ทรานสโพส, เดาคีย์ (ให้คะแนนทั้ง 24 คีย์), ตัวช่วยคาโป้, อ่านข้อความจูนสาย
- `ocr.js`: ขยายรูปเป็นกว้าง ~2000px แล้วแปลงเป็นขาวดำ 2 แบบ (Otsu + local mean ทำให้ลายน้ำสีเทาหายไป) จากนั้น OCR 2 รอบ (sparse บนเส้นบาง + auto บนเส้นปกติ) แล้วรวมผล คำที่ไม่ชัดจะอ่านซ้ำด้วย whitelist ตัวอักษรคอร์ด
- `detect.js`: คัดคำ OCR ว่าคำไหนเป็นคอร์ด/บรรทัดคอร์ด และตัดคำที่ติดกับเนื้อร้อง (ภาษาไทยจะกลายเป็นตัวอักษรขยะความมั่นใจต่ำ) รวมผลหลายรอบ และหาตำแหน่งหมึกตรงจุดที่แตะ
- `render.js`: วาดคอร์ดใหม่ทับรูป ใช้สีพื้นกระดาษและสีหมึกที่สุ่มจากรอบๆ คอร์ดเดิม และปรับขนาดตัวอักษรให้เท่าของเดิม
- `diagrams.js`: ตารางนิ้วคอร์ด เลือกจากท่าเปิดมาตรฐาน → ท่าทาบทรง E/A → ค้นหาท่าที่จับได้จริง (ไม่เกิน 4 นิ้ว) ตามลำดับ
- `fretboard.js`: สเกลบนคอกีตาร์ (เขียนชื่อโน้ตตัวอักษรละหนึ่งตัวต่อขั้น เช่น F# เมเจอร์มี E#) วาดเป็น SVG
- `storage.js`: เพลงล่าสุด (IndexedDB) และค่าตั้งค่า (localStorage)
- `main.js`: UI
- `scripts/copy-tesseract.mjs`: คัดลอก engine OCR และข้อมูลภาษาอังกฤษไปที่ `public/tesseract` ตอน `npm install` ทำให้ใช้ได้แบบออฟไลน์

## Deploy to GitHub Pages

Workflow ที่ `.github/workflows/deploy-pages.yml` จะ build และ deploy เว็บอัตโนมัติเมื่อ push ไป branch `main` หรือสั่งจากแท็บ Actions

1. สร้าง GitHub repository แล้ว push โปรเจกต์นี้ขึ้น branch `main`
2. ใน repository ไปที่ **Settings → Pages** แล้วเลือก **GitHub Actions** เป็น Build and deployment source
3. รอ workflow `Deploy to GitHub Pages` ทำงานสำเร็จ จากนั้นเปิด URL ที่แสดงใน deployment

GitHub Pages เป็น static hosting จึงใช้ upload เพลงจากเครื่องและ Chord Shift ได้ แต่ไม่มี Node.js server สำหรับ `/api/youtube` ทำให้การแกะเสียงจาก YouTube ใช้ไม่ได้

## Deploy เว็บที่รองรับ YouTube

ใช้ Render เพื่อรันทั้งหน้าเว็บและ YouTube API บน service เดียวกัน:

1. Push repository นี้ไป GitHub แล้วเข้า [Render](https://render.com/) และเลือก **New → Blueprint**
2. เชื่อม repository `Chord-Shift` และเลือก branch `main`; Render จะอ่าน `render.yaml`
3. กด **Apply** แล้วรอ build/deploy เสร็จ จากนั้นเปิด URL `.onrender.com` ที่ Render ให้มา

Blueprint จะติดตั้ง yt-dlp พร้อมตรวจ SHA-256, build เว็บ และเริ่ม Node server ที่เสิร์ฟทั้งหน้าเว็บกับ `/api/youtube` บน origin เดียวกัน แผน Free อาจ sleep เมื่อไม่มีคนใช้ จึงอาจต้องรอให้ service ตื่นก่อนคำขอแรก
